ANSWER_1: The Course Materials Portal cannot start correctly because the course-portal process is being denied access when it tries to read its own configuration file, portal.conf.
ANSWER_2: The file portal.conf is owned by root with group course-portal, and its permissions are -rw------- (600), meaning only the file's owner has any access at all, group and others have none. The course-portal account has uid 995, so it is not root and cannot use owner permissions. Its group is also course-portal (gid 995), which matches the file's group, but since the group permission bits are set to 0 (no read, write, or execute), group membership doesn't help, the account is locked out entirely.
ANSWER_3: 640
ANSWER_3_WHY: 400 only grants read access to the owner, so course-portal (a group member, not the owner) would still be denied. 755 and 777 both add execute permission, which a plain text config file never needs to run. 777 is worse still: it opens read, write, and execute to every user on the system (the "others" category), meaning any local account could view or tamper with sensitive configuration values. 640 is the minimum change that fixes the actual problem, it adds read-only access for the group course-portal is already in, without touching anything else.
